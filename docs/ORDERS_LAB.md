# ASmel — Заказать разработку · LAB

## Назначение

Существующий публичный сайт ASmel (GitHub: inco-art/asmel-site) дополняется блоком «Заказать разработку» под каталогом приложений. Предложения: сайты/лендинги, веб-сервисы, Android и программы для ПК, автоматизация. Речь о запросе на оценку, а не о гарантированной цене или сроке.

## Сейчас реализовано

- Переходы из шапки и первого экрана к форме.
- Компактный адаптивный блок DeepSpace / ASG Dark Web, без внешних зависимостей: тёмные поверхности, ограниченное стекло, один бирюзовый акцент, разные размеры карточек, достаточные области для touch, читабельный текст.
- Поля: тип работы, имя, контакт (email/Telegram/телефон), описание (от 20 до 4000 знаков), бюджет и срок (необязательны).
- Режим **черновика**: проверка формы, локальный текстовый предпросмотр, копирование в буфер, сохранение TXT. Никакой автоматической отправки, слежения, cookies или localStorage. Запрещено объявлять заявку доставленной.
- Код уже поддерживает дополнительный **HTTPS POST endpoint**: отправка JSON, 15-секундный таймаут, отсутствие cookies, подтверждение приёма только при получении HTTP 2xx с JSON `{"status":"received","request_id":"ASG_..."}`. Однако в `index.html` сейчас стоит `data-endpoint=""`, поэтому этот путь отключён.
- Поле-ловушка для ботов и базовая браузерная валидация. Они не заменяют серверную защиту.

## Не реализовано — для настоящего приёма заявок

1. Подтвердить официальный **публичный бизнес-email/канал** для ответов клиентам. Почта личных и семейных сервисов не используется без явного решения.
2. Выбрать и защитить серверный приёмник: HTTPS, проверка размера/типов, антиспам и rate limiting, логирование только технической диагностики без открытых персональных полей, резервирование и права доступа.
3. Безопасный маршрут доставки: уведомление в согласованный почтовый ящик и/или в отдельный закрытый реестр заказов, с идентификатором обращения и статусами. Для связки с Notion токен должен жить только на стороне сервера.
4. До публичного включения приёма персональных данных: политика конфиденциальности, сроки хранения и удаление, контакты ответственного, законные основания обработки, проверка применимых правовых требований.
5. Ручные тесты доставки, отказов сервера, повторных запросов, спама и обработки дублей. Только потом настраивать `data-endpoint` и публиковать форму.
6. В будущем: вложения, техническое задание, предварительная оценка, кабинет клиента, статусы «Новая / Оценка / Согласование / В работе / Готово», цены — после утверждения.

## Контракт API (будущее)

`POST https://<собственный-проверенный-домен>/api/orders`

`Content-Type: application/json`

JSON: `type`, `name`, `contact`, `description`, `budget`, `timeline`.

Успех — HTTP 2xx и JSON `{"status":"received","request_id":"ASG_20261110_0001"}`. Сервер должен гарантировать сохранение/очередь до такого ответа. Ошибка, таймаут или неверный receipt — не считается доставкой; UI показывает локальный черновик.

## Безопасность релиза

- Только отдельная ветка `feature/public-order-intake-lab`. Не изменять без проверки main или публичную публикацию.
- Работающий исходник `index.html` сохранён в `backups/` изолированной локальной папки.
- Старые карточки «Мой табель», INCO Compress и Key Reserve остаются без изменений.
- Changelog в шапке всех новых файлов; никакие email/пароли/токены не хардкодятся.
- Проверить навигацию, мобильную ширину, клавиатуру, копирование TXT, длинные вводы, вывод пользовательского текста только через `textContent`.
